# Разработка интерпретатора языка программирования Nolang  
  
# Постановка  
  
Система предназначена для разбора, семантического анализа и выполнения математических выражений и алгоритмов, описанных  
в текстовом виде.  
Система должна поддерживать три уровня сложности:  
  
- базовый калькулятор,  
- язык с динамической типизацией,  
- язык со статической типизацией.

# Этап 1: Алгебраический калькулятор  
  
## Функциональные требования  
  
- Синтаксис: Поддержка арифметических операторов (`+`, `-`, ``, `/`, `^`), унарных операторов,  
  скобок и факториала.  
- Переменные: Поддержка именованных переменных. Присваивание значений. Повторное присваивание  
  разрешено.  
- Типизация: Динамическая. Система самостоятельно определяет тип данных (целое число или  
  вещественное число) на этапе  
  выполнения.  
- Поведение: Использование переменной до ее инициализации должно приводить к остановке выполнения с  
  сообщением об  
  ошибке.  
  
### Приоритеты и ассоциативность  
  
1. Группирование:  
    - скобки `(...)`;  
    - абсолютные скобки `| ... |`  
2. Постфиксный факториал `!`  
3. Возведение в степень `^`  
    - операция правоассоциативная  
4. Унарные префиксные операторы `+`, `-`  
    - операции правоассоциативные  
5. Умножение и деление ``, `/`  
    - операции левоассоциативные  
6. Сложение и вычитание `+`, `-`  
    - операции левоассоциативные  
  
### Переменные  
  
- Переменная создается оператором присваивания  
- Использование переменной до первого присваивания является ошибкой  
- Повторное присваивание разрешено  
  
### Типизация  
  
Динамическая  
  
### Способ выполнения  
  
Интерпретируемый  
  
## Обоснование решения  
  
### Почему выбран функциональный подход  
  
Интерпретатор опирается на три ограничения:  
  
1. Формальная спецификация AST. Типы синтаксического дерева определены как sealed-иерархии (`Value`,  
   `Eval`, `Result`, `EvalError`, `ScopeError`). Множество возможных значений конечно и известно на  
   этапе компиляции.  
  
2. Неизменяемость данных. Все структуры данных - `record`. Изменение состояния программы создает  
   новый объект `Environment` вместо модификации существующего.  
  
3. Отсутствие побочных эффектов. Вычисление представлено значением типа `Eval<A>`, которое при  
   исполнении возвращает `Result<A>`. Вывод накапливается в `Environment.outputBuffer`, а не  
   выполняется через глобальный `PrintStream`.  
  
4. Проверка ошибок как значений, не побочных сигналов  
  
### Формула  
  
```  
Формальная спецификация AST  
+ неизменяемость данных  
+ отсутствие побочных эффектов  
=  
структурная индукция  
```  
  
### Структурная индукция  
  
Программа представляет собой дерево. Каждый узел дерева конструируется из дочерних узлов по  
фиксированным правилам.  
  
Метод доказательства:  
  
- Базис: доказать корректность для листовых узлов (числа, булевы значения).  
- Шаг: для каждого типа составного узла доказать: если дочерние узлы корректны, то родительский узел  
  корректен.  
- Заключение: любое дерево, построенное из этих правил, корректно.  
  
Корректность дерева следует из правил его построения, примененных рекурсивно. Это свойство  
обозначается как «дерево доказывает само себя»: валидность целого дерева является следствием  
валидности каждого конструктора узла.  
  
### Минимизация тестирования с сохранением гарантии выполнения  
  
Следствие структурной индукции: множество необходимых тестов конечно.  
  
Вместо тестирования всех возможных программ (множество бесконечно) тестируются:  
  
- базисные случаи для каждого листового типа;  
- индуктивные шаги для каждого типа составного узла.  
  
### Гипотеза  
  
Если AST формально специфицирован, данные неизменяемы, а вычисление не содержит побочных эффектов,  
то структурная индукция обеспечивает доказательство корректности для всех программ, выразимых в языке.  
Тестирование сокращается до проверки базисных случаев и индуктивных шагов для каждого типа узла.  
  
## Выполнение  
  
### Сборка  
  
```shell  
mvn clean package  
```  
  
### Запуск: Интерактивный режим (REPL)  
  
```shell  
java -jar target/nolang-1.0-SNAPSHOT.jar algebraic  
```  
  
```text  
> print(abs(-3))  
3  
> print(1/0)  
Division by zero  
```  
  
### Выполнение из файла  
  
```shell  
java -jar target/nolang-1.0-SNAPSHOT.jar algebraic src/test/resources/algebraic/cli-test-input.txt  
```  
  
Ожидаемый вывод:  
  
```text  
3  
8  
120  
```

# Этап 2: Транслятор: динамическая типизация  
  
## Функциональные требования  
  
- Логические операции: Поддержка операторов сравнения (`>`, `<`, `==`, `!=`) и логических связок (  
  `AND`, `OR`, `NOT`).  
- Управление потоком: Реализация условных конструкций (`if/else`) и циклов (`while`).  
- Функции: Возможность объявления пользовательских функций, передача аргументов, поддержка рекурсии.  
- Встроенные функции: Предоставление набора стандартных математических функций (например, `sin`,  
  `abs`, `pow`).  
  
### Типизация  
  
Динамическая  
  
### Способ выполнения  
  
Интерпретируемый  
  
---  
  
# Этап 3: Транслятор: статическая типизация  
  
## Функциональные требования  
  
- Объявление типов: Переменные и параметры функций должны иметь явно указанный тип (`int`, `float`,  
  `boolValue`).  
- Проверка типов: Система должна отклонять выполнение программы на этапе компиляции (до начала  
  выполнения) при попытке  
  присвоить значение несовместимого типа или передать аргумент неверного типа в функцию.  
- Область видимости: Поддержка вложенных областей видимости переменных.  
  
### Типизация  
  
Статическая  
  
### Способ выполнения  
  
Компилируемый  
  
---  
  
# Нефункциональные требования и ограничения  
  
- Обработка ошибок: Синтаксические ошибки должны фиксироваться с указанием номера строки и позиции  
  символа.  
- Расширяемость: Архитектура синтаксического анализатора должна позволять добавлять новые  
  синтаксические конструкции без  
  модификации ядра системы.  
- Независимость: Система не должна зависеть от внешних сетевых ресурсов или файловых систем во время  
  выполнения  
  вычислений.
