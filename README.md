# Stage 1: Algebraic calculator

## Постановка

- Разработать EBNF-грамматику лексем и синтаксических правил для объявлений и операторов присваивания
- Реализовать парсинг с помощью ANTLR4 и генерацию AST
- Предметная область: школьная алгебра
- Типизация: вывод типа в runtime (целые и дробные числа)
- Переменные: строгая инициализация до использования, переопределение разрешено
- Идентификаторы: `[a-zA-Z_][a-zA-Z0-9_]*`, чувствительны к регистру
- Приоритеты (от высшего к низшему): скобки `()`, степень `^`, унарные (`+`, `-`, `| |`, `!`), умножение/деление `*/`,
  сложение/вычитание `+-`

### Программа

- Программа представляет собой последовательность операторов
- Результат программы - это результат последнего оператора
- Если программа не содержит операторов, результатом является `VoidResult`
- Если внешнему API требуется получить значение программы, используется извлечение `Value` из `ValueResult`
- При отсутствии `ValueResult` внешний API должен явно сообщить об отсутствии значения, а не возвращать `null`

### Приоритеты и ассоциативность

1. Группирование:
   - скобки `(...)`;
   - абсолютные скобки `| ... |`
2. Постфиксный факториал `!`
3. Возведение в степень `^`
   - операция правоассоциативная
4. Унарные префиксные операторы `+`, `-`
   - операции правоассоциативные
5. Умножение и деление `*`, `/`
   - операции левоассоциативные
6. Сложение и вычитание `+`, `-`
   - операции левоассоциативные

### Переменные

- Переменная создается оператором присваивания
- Оператор присваивания возвращает VoidResult
- Использование переменной до первого присваивания является ошибкой
- Повторное присваивание разрешено
- На Stage 1 переменная не имеет фиксированного объявленного типа
- Тип значения определяется во время выполнения:
  - `IntValue` соответствует `INTEGER`;
  - `DoubleValue` соответствует `FLOAT`

### Ограничения

- `Algebraic calculator` работает с вещественными числами. Операции, не определенные в вещественных числах, завершаются
  исключением

# Stage 3: Разработка типизированного интерпретатора

постановка

- переменные должны при объявлении иметь тип
- переменным нельзя присвоить данные другого типа
- выражение (expression) должно иметь тип и оно должно быть вычислено до выполнения, в compile time
- функция должна иметь типы аргументов и результата - типы задаются в исходном коде
- тип тела функции должно сходиться / совпадать по типу с ожидаемым результатом - эта проверка должна выполняться в
  compile time
- компиляция кода в байт код jvm
+ комментарии

Переменные: Повторное объявление с тем же типом разрешено, с другим типом - ошибка компиляции
Переменные, область видимости: Перекрытие разрешено
Функции: Переопределение перезаписывает определение
Встроенные функции: пользовательское определение с именем встроенной => ошибка в точке объявления

план:

- реализовать поддержку комментариев
- устранить конфликт helpStat и ternary
- разработать синтаксис - грамматику StaticTyped.g4
- обозначение типа переменной
- обозначение типов параметров и результата функции
- реализовать семантический анализ - TypeChecking
- проверка соответствия типа переменной, параметров и результата функции типу переданного значения
- реализовать BytecodeGenerator
- реализовать Classloader

# Cheatsheet

Настройка для работы с antlr без maven плагина

```shell
# ANTLR4 в .bashrc
export ANTLR_JAR=~/.local/share/java/antlr-4.13.2-complete.jar

antlr() {
    java -jar "$ANTLR_JAR" "$@"
}

grun() {
    java -cp "$ANTLR_JAR:target/classes" org.antlr.v4.gui.TestRig "$@"
}
```

## Отладка грамматики

```shell
# Компиляция грамматики без плагина (в /tmp, для отладки)
mvn clean compile
# see how ANTLR translates your left-recursive rules
antlr -o /tmp -Xlog src/main/antlr4/com/nokhrin/interpreter/StaticTyped.g4
# сгенерирует классы лексер, парсер, слушатель в /tmp/src/main/antlr4/com/nokhrin/interpreter

# Визуализация
# дерево в консоль
grun com.nokhrin.nolang.StaticTyped prog -tree < src/test/resources/StaticTyped/possible_problems.txt
# дерево в gui
grun com.nokhrin.nolang.StaticTyped prog -gui < src/test/resources/StaticTyped/possible_problems.txt
# токены
grun com.nokhrin.nolang.StaticTyped tokens -tokens < src/test/resources/StaticTyped/possible_problems.txt
```
